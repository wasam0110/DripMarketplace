# Backend pre-ship checkpoint 19: activate the security suite

19 October 2026. Backend only. The 162-item audit remains **IN PROGRESS**.
This checkpoint changes tests and documentation. Application code, frontend,
configuration, migrations and provider integrations were not changed. No local
secrets were read and no Git staging, commit, push or deployment commands were run.

## Repair

`tests/security/test_auth.py` had an unconditional module skip, a separate client
without the shared database override, nonexistent account fixtures, stale routes,
an invalid-signature token presented as an expiry test, and permissive assertions.
Some callback cases accepted success without checking persisted payment state.

The module now contains **47 cases** that collect independently. Execution uses
the shared disposable PostgreSQL fixture and fakeredis. Missing TEST_DATABASE_URL
causes an explicit fixture skip; no deployment users or merchant credentials are
required. Fixtures create two seller accounts with different wallet balances,
customer/admin accounts, a public product and inventory. Signing uses the test
keys generated by the existing root conftest.

Coverage within the repaired module:

- Exact login/register/reset throttle thresholds (5/3/3), remaining/retry headers,
  counter TTL, blocked-request effects and untrusted forwarding-header rejection.
  Registration uses the actual account service and a mocked worker queue.
- Matching reset responses for existing/missing accounts.
- Valid-token controls, tampered payloads, correctly signed expired tokens, malformed
  or absent tokens, role/version mismatch, deleted/unverified accounts, revocation,
  wrong audience and wrong issuer.
- Current product/inventory write routes reject the other seller with exact
  403/404 outcomes; wallet reads return the authenticated seller's balance.
  Role denials and account-order authentication are checked with valid controls.
- GET/POST callbacks reject missing/bad hashes and missing transaction IDs against
  a real pending payment. Correct hashes cannot bypass amount/currency checks.
  Rejections preserve product/inventory/wallet/order/payment snapshots and retain
  unverified callback audits where appropriate. Valid failed-payment callbacks
  provide a positive control for the real parser and handler.
- Callback IP/size gates, SQL-like search strings, script search input, traversal
  slug examples and the existing registration-password length validator.

PayFast transport is blocked by failing mocks in this module; queue calls are
mocked. Synthetic credentials enable local callback parsing only. Successful online
payment reconciliation, merchant acceptance and real queue delivery are separate
verification. The size cases exercise the callback's 16 KiB cap and registration's
password validator; they do not certify a global request limit or a login length cap.
